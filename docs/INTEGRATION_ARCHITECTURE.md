# سند معماری یکپارچه‌سازی با سیستم مدیریت مجموعه

## 📋 معرفی

این سند نحوه یکپارچه‌سازی سامانه «گزارش و طرح‌درس روزانه مربیان» با **سیستم مدیریت موجود مجموعه** (نهضت تربیتی حضرت سیدالشهدا علیه‌السلام) را شرح می‌دهد.

---

## 🎯 هدف

- **استفاده از زیرساخت موجود** مجموعه (سرور، دامنه، پایگاه‌داده)
- **جلوگیری از دوگانه‌کاری** در مدیریت کاربران و شعب
- **حفظ استقلال** سامانه مربیان در عملکرد روزمره
- **امکان همگام‌سازی** داده‌های پایه از سیستم مرکزی

## 🔌 نحوه یکپارچه‌سازی

### مرحله ۱: همگام‌سازی داده‌های پایه (API-based)

#### الگوی پیشنهادی: Pull-based Sync

```
سامانه مربیان  ──── GET /api/sync/branches ────►  سیستم مدیریت
                          ◄────── JSON branches ────
                              [{"id":1, "name":"شعبه بانو حدادیان", ...}]

سامانه مربیان  ──── GET /api/sync/users ────────►  سیستم مدیریت
                          ◄────── JSON users ──────
                              [{"id":"u1", "name":"...", "role":"INSTRUCTOR", ...}]
```

#### پیاده‌سازی در سامانه مربیان:

۱. **افزودن مدل `SyncLog`** برای ثبت زمان آخرین همگام‌سازی:
```prisma
model SyncLog {
  id          String   @id @default(cuid())
  entityType  String   // "branch" | "user"
  lastSyncAt  DateTime @default(now())
  status      String   // "success" | "failed"
  recordsCount Int     @default(0)
  error       String?
}
```

۲. **افزودن API همگام‌سازی** (`/api/sync`):
   - فراخوانی API سیستم مرکزی
   - به‌روزرسانی جدول‌های محلی
   - ثبت در SyncLog

۳. **اجرای خودکار** (Cron job روزانه یا دستی توسط مدیر)

### مرحله ۲: اشتراک احراز هویت (SSO) - اختیاری

#### الگوی پیشنهادی: JWT-based SSO

```
┌─────────────┐     ۱. ورود       ┌─────────────────┐
│   کاربر     │ ───────────────► │ سیستم مدیریت    │
│             │                  │ (احراز هویت)    │
└──────┬──────┘                  └────────┬────────┘
       │                                  │
       │   ۲. تولید JWT مشترک              │
       │ ◄────────────────────────────────┘
       │
       │   ۳. انتقال به سامانه مربیان با توکن
       ▼
┌─────────────┐     ۴. اعتبارسنجی JWT  ┌─────────────────┐
│ سامانه     │ ────────────────────► │ سیستم مدیریت    │
│ مربیان     │                       │ (اعتبارسنجی)    │
└─────────────┘ ◄─────────────────── └─────────────────┘
                       ۵. داده‌های کاربر
```

#### پیاده‌سازی:
- استفاده از **کلید عمومی/خصوصی RSA** برای امضای JWT
- سامانه مربیان کلید عمومی سیستم مرکزی را برای اعتبارسنجی دارد
- زمان انقضای توکن کوتاه (۱ ساعت)
- به‌روزرسانی خودکار توکن (refresh token)

### مرحله ۳: رویدادهای Webhook (Push-based) - اختیاری

#### الگوی پیشنهادی: Event-driven Webhooks

```
سیستم مدیریت                     سامانه مربیان
─────────────                    ─────────────
新增 کاربر جدید   ──────►  POST /api/webhooks/user-created
                                 {"userId": "u1", "name": "...", ...}

حذف شعبه         ──────►  POST /api/webhooks/branch-deleted
                                 {"branchId": 1, ...}

تغییر نقش کاربر  ──────►  POST /api/webhooks/user-role-changed
                                 {"userId": "u1", "oldRole": "...", "newRole": "..."}
```

#### مزایا:
- همگام‌سازی بلادرنگ
- کاهش بار روی سیستم مرکزی
- داده‌ها همیشه به‌روز

## 🔐 ملاحظات امنیتی

### ۱. احراز هویت API-to-API
```http
POST /api/sync/branches HTTP/1.1
Host: management.yourdomain.ir
Authorization: Bearer <shared-secret-token>
Content-Type: application/json
```

- استفاده از **توکن مشترک** بین دو سیستم (با چرخش دوره‌ای)
- محدودیت IP به سرور مجموعه
- استفاده از HTTPS (الزامی)

### ۲. رمزنگاری در انتقال
- همه ارتباطات بین دو سیستم از طریق **HTTPS**
- گواهی SSL معتبر برای هر دو دامنه

### ۳. محدودیت دسترسی API
- API همگام‌سازی فقط برای **خواندن** (Read-only) از سیستم مرکزی
- سامانه مربیان هرگز داده‌های سیستم مرکزی را تغییر نمی‌دهد
- اعمال rate limiting (مثلاً ۱۰۰ درخواست در دقیقه)

### ۴. حریم خصوصی داده‌ها
- فقط داده‌های **لازم** همگام می‌شوند (نه همه فیلدها)
- اطلاعات حساس (مثل رمز عبور) هرگز منتقل نمی‌شود
- رعایت اصل حداقل دسترسی (Principle of Least Privilege)

## 🚀 پیاده‌سازی گام به گام

### گام ۱: استقرار اولیه (بدون یکپارچه‌سازی)

۳. کاربران و شعب را به‌صورت دستی وارد کنید (با seed موجود)

۱. Cron job در سامانه مربیان برای همگام‌سازی روزانه

۳. مدیریت تعارضات (مثلاً کاربر حذف‌شده در مرکزی)

۱. تعریف کلیدهای RSA بین دو سیستم
۲. پیاده‌سازی login مشترک

### گام ۵: Webhookها (Phase 4 - اختیاری)
۱. تعریف endpointهای webhook در سامانه مربیان
۲. فعال‌سازی رویدادها در سیستم مرکزی

## 🔧 اسکریپت همگام‌سازی (نمونه)

```typescript
// scripts/sync-from-central.ts
import { db } from "../src/lib/db";

const CENTRAL_API = process.env.CENTRAL_API_URL || "https://management.yourdomain.ir/api/v1";
const API_TOKEN = process.env.CENTRAL_API_TOKEN;

async function syncBranches() {
  const res = await fetch(`${CENTRAL_API}/branches`, {
    headers: { Authorization: `Bearer ${API_TOKEN}` },
  });
  const { branches } = await res.json();

  for (const b of branches) {
    await db.branch.upsert({
      where: { code: b.code },
      create: { ...b },
      update: { ...b },
    });
  }
}

async function syncUsers() {
  const res = await fetch(`${CENTRAL_API}/users`, {
    headers: { Authorization: `Bearer ${API_TOKEN}` },
  });
  const { users } = await res.json();

  for (const u of users) {
    await db.user.upsert({
      where: { phone: u.phone },
      create: { ...u, passwordHash: "PENDING_SYNC" },
      update: { name: u.name, role: u.role, branchId: u.branchId, active: u.active },
    });
  }
}

// اجرا
syncBranches().then(syncUsers).then(() => console.log("✅ همگام‌سازی انجام شد"));
```

## ⚠️ ملاحظات و ریسک‌ها

### ۱. تعارض داده‌ها
- **ریسک:** کاربر در سیستم مرکزی حذف شود اما در سامانه مربیان گزارش‌هایی داشته باشد
- **راه‌حل:** به جای حذف، کاربر را غیرفعال (active=false) کنید؛ داده‌های آموزشی حفظ می‌شود

### ۲. قطعی ارتباط
- **ریسک:** سیستم مرکزی موقتاً در دسترس نباشد
- **راه‌حل:** سامانه مربیان با داده‌های محلی ادامه می‌دهد؛ همگام‌سازی در زمان بازیابی انجام می‌شود

### ۳. تغییرات schema
- **ریسک:** فیلدهای سیستم مرکزی تغییر کند
- **راه‌حل:** نسخه‌بندی API (مثلاً `/api/v1/`) و انتقال تدریجی

### ۴. توکن‌های امنیتی
- **ریسک:** لو رفتن توکن API
- **راه‌حل:** چرخش دوره‌ای (ماهانه) و ذخیره امن در متغیرهای محیطی
